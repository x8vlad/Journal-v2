**файл**: /Journal-v2/core/**autoloader.php**

**зачем нужен**: избавляет от require в каждом файле 
как работает: функция **spl_autoload_register** это автозагрузчик **файлов** в php
когда в коде встречается **new Class()** php не падает с ошибкой что класс не найден, а вызывает функцию **spl_autoloadad_register**
**как работает**: подставялет если НЕТ немспейса class=User, а 
если есть немспейс то значение: фул немспейса и названия класса для переменной ($class) 
напрмиер  немспей в классе: /app/store/ сам класс: new Class.php
в class попадет: /app/store/Class.php
меняет слеши в завиимости от ОС
перемная **path** формирует относительный путь ../app/store/Class.php

**файл**: /Journal-v2/core/**Loader.php**

**зачем нужен**: **создание обьктов**  

**как работает**: 
1) __конструктор, для инициализации registry чтоб контроллеры и модели имели доступ к ДБ

2) controller($route, $method), метод для вызывания у класса определенный метод ($this->registry) чтоб взаимодействовать с сервисами

3) model($name_model) для вызовки моделей из ../app/model 
создает уникальный ключ registry_key для того чтоб не вызвать класс n раз подряд
а так в проверке был ли ранее вызвал метод если да то пропускает и сразу вызывает его (тк в памяти он уже етсь) 

4) view для отрисвоки вью (path_view, $data = [])  чтоб к data обращатся не через [], а через -> конвертируем в обьект 
далше создаем файл вью и после провярем есть ли такой если да то **ob_start()** функция для сохранения даннх перед отпарвкой подклчюаем наш файл вью где верстка 
и в переменную отупут_контет ложим то что гет-нулось из буфера и очищаем буфер также отключаем буферизацию

файл: /Journal-v2/core/**Router.php**

**зачем нужен**: связывает url браузера с тем какой контроллер должен вызвать
(model  - controller  - view)
DB date - modify date - show data
**как работает**: конструктор определяет какой uri, а такжек какой метод GET/POST
add метод нужен для добавления в routes[] uri, controller, method (get, post) создан чисто чтоб помочь 
добалвять данные для методов **get, post**
метод get добавляет юри и контроеллер и метод ГЕТ исполльуется во фронт контроллере: 
        get ("uri", controller) нужен 
```
router->get("announcement", "app\\controller\\announcement\\AnnouncementController");
router->post("announcement/add", "app\\controller\\announcement\\AnnouncementController");
```

КАК РАБОТАЕТ ПРИЛОЖЕНИЕ С ЭТИМИ СЕРВИСАМИ все происходит во **фронт-контроллере**:
1) вызываем в самом начале один раз autoloader.php который отвечате за авто-загразку всех классов 
2) Создаем регистри (хранилище обьектов) и сетим туда базу данных также делаем и для **лоадера**
```
$registry = $registry = new \core\Registry();
$registry->set('db', new \core\Dbh());

$loader = new \core\Loader($registry);
$registry->set('load', $loader);

$router = new \core\Router();
$router->get("", "app\\controller\\testClass");

$class_name = $router->match();

$loader->controller($class_name, "");
```
3) дальше мы создаем Роутер, его целью определить url выбрать ресурс котрый требуется и в методе
match() он пройдется по всем (если гет метод то) по всемм роутам где был ->get() и посаставит этот uri
если найдется то **возвращает** return app\controller\testClass
4) как мы помнил в Loader у нас етсь такие строки:
``` 
$class = new $route($this->registry); это равняется $class = app\controller\testClass($this->registry) 
return $class->$method();
```
5) когда php видит слво new то автоматически передает это к GITаутолоадеру, коттрй и отвечает за автозагрузку классов и изза рекваитр он попадает в RAM
6) далее так как В паамяти уже естть класс то в **Loader** $class = new $route($this->registry); то  втой строке
на месте $class уже обьект $testClass
7) $loader->controller($class_name, ""); запускает работу метода у данного класса
